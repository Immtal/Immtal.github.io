Hexo搭建及所遇到的问题

网络问题：HTTP->SSH

我搭建个人网站主要参考的是这篇知乎回答。其中在配置_config.yml时，我根据他的图片配置无法成功。具体是hexo d会提示输入用户名和密码，但是报错了。Chatgpt告诉我从21年开始，取消了用户名和密码访问github的方法，转而用token代替。但我生成token后，仍然无法连接。我看了知乎的另一篇回答，然后更改了github部署，改成了 repository: git@github.com:username/username.github.io.git # 你的仓库地址,就成功了，据Chatgpt说这是SSH连接方式，而repository: https://github.com/username/username.github.io.git叫做HTTP协议方式（大致是这个意思）。知其然而不知其所以然，anyway，先这么用着。

然后还有一点，我要对repository里面与个人网页有关的仓库进行设置，Settings -> Pages -> Build and deployment -> Branch -> 把None修改为gh-pages（因为我在_config.yml里设置的是branch: gh-pages）

主题：butterfly

在设置主题butterfly时我参考了这篇CSDN文章。其中我采取了他的升级建议，但是并未完全理解，后续若要更换主题，可以参考理解一下。

  • 为了減少升级主题带来的不便，我们可以把主题文件夹中的 _config.yml 重命名为 _config.butterfly.yml，复制到 Hexo 根目录下与_config.yml同级。

  • Hexo会自动合并主题中的_config.yml和 _config.butterfly.yml ，如果存在同名配置，会使用_config.butterfly.yml的配置，其优先度较高。所以像和博客网址相关联的固定资料可以设置在_config.yml中，比如博客的标题、作者信息和邮箱等等资料，而和主题样式相关的配置放在 _config.butterfly.yml 中，那么在将来你想换一个主题是很方便的。

嗷，可能在终端直接用http访问github，git clone -b master https://github.com/jerryc127/hexo-theme-butterfly.git themes/butterfly，无法克隆他的仓库（很可能是网络问题，即使我使用了魔法，依然遭遇阻碍）。但是用ssh可能会好一点，不过我没有尝试，我用的是gitee，git clone -b master https://gitee.com/immyw/hexo-theme-butterfly.git themes/butterfly。

Hexo的相对路径问题

_config.butterfly.yml文件在hexo的根目录myBlog下，图片wallhaven-6degg7.jpg在myBlog/source/img/wallhaven-6degg7.jpg，为什么tag_img: /img/wallhaven-6degg7.jpg这里的相对路径没有写source文件夹？

  • 答：在 Hexo 中，所有的静态资源（如图片、CSS、JavaScript 文件等）通常存放在 source 目录下。对于你提供的图片路径：myBlog/source/img/wallhaven-6degg7.jpg这个路径是在 source/img/ 目录下的一个图片文件。对于 Hexo 来说，这个路径是相对于 myBlog/source/ 目录的。当 Hexo 生成网站
    时，它会将 source 目录下的内容复制到生成的 _site 目录，并保持原有的结 构。在 Hexo 配置文件中，/img/wallhaven-6degg7.jpg 是相对网站根目录的路径，而不是相对本地文件系统的路径。因此，/img/ 指的是 Hexo 网站生成后在 _site 目录中的 img 文件夹。
    简而言之，/img/ 会映射到 source/img/ 目录，在你生成的静态网站中，图片会被正确地放在 /img/ 路径下。——摘自Chatgpt

keywords 与 tags 的区别

在 Hexo 中，keywords 不会像 tags 那样直接在页面上显示。tags 会被展示在文章的底部或文章页面中，作为分类的一部分，便于用户查看和点击，而 keywords 主要是面向搜索引擎的优化信息，并不会直接出现在页面上。

  • 在网页源码中：keywords 会被嵌入到 HTML 页面<meta>标签里，通常位于<head>部分，用于搜索引擎索引。这对用户来说是不可见的，但对于搜索引擎的爬虫是可见的。
  • 社交媒体预览：如果你在分享文章链接时使用了社交媒体（如微博、微信等），有些平台可能会通过 meta 信息获取文章的摘要、标题和关键词。尽管它不会像 tags 那样显示在文章页，但它可能会影响到社交媒体平台上文章的呈现。

总结来说，keywords 主要是在 SEO（Search Engine Optimization，搜索引擎优化）方面发挥作用，不会直接在你的网站页面上显示给访客，主要还是服务于搜索引擎。

数学公式渲染

我最终选择了katex。
我尝试了mathjax，但是很多教程（比如butterfly官方文档）会提示下载hexo-renderer-kramed --save，但因为这个渲染器很多年没人维护（见这位博主的描述），所以安装后会提示有五个漏洞，并且以我目前的能力无法解决。而且，听说无法很好地显示多行公式。不选择mathjax的主要原因是很久没人维护了。
所以我选择了katex，根据butterfly官方文档或者这位博主的方法，可以进行katex配置，二者的区别的插件不同，但我没有进行详细对比，效果相似。我选择的是后者，@neilsustc/markdown-it-katex。

还有一个很重要的问题，我并没有完全搞清楚。在网页上，$a^2 + b^2 = c^2$ 可以被渲染为公式 a2+b2=c2a^2 + b^2 = c^2a2+b2=c2，但是 $ a^2 + b^2 = c^2 $ 无法被渲染为公式，会保留原字符。但在vscode上用markdown预览器会均显示为公式。看来问题出在空格上，或许是katex要求的latex语法比较严格。但mathjax不会，$a^2 + b^2 = c^2$ 和 $ a^2 + b^2 = c^2 $ 都可以渲染为公式 a2+b2=c2a^2 + b^2 = c^2a2+b2=c2。
